# WSA1 names that spelled O with the digit 0 (2026-11-06)

Lane open9/zero-for-o. Register item **N-b796721c**.

Some SX-WSA1R captions are typed in the ROM with character code 0x30, the digit zero, for capital O:
`DISK L0AD`, `FL0PPY`, `F0RMAT`, `FILE SELECTI0N`, `LF01`. Six of the machine's seven Latin faces draw cells 0x30
and 0x4F alike, so the zero never shows on screen (`notes/prom_b_screens_round8.py --glyphs`). Labels named after
those captions copied the zero: `MidiFileL0ad_LcdKeyRow1`, `Paint_MidiFileL0ad`, `L0adSingleS0und`, `DL_*F0rmat*`, the
`ButtonTable_MeasureC0py_*` and `ButtonTable_S0ngC0py_*` families, and more.

The owner, 2026-11-06: **"Normalise: rename across the whole tree, L0ad→Load, S0und→Sound, C0py→Copy, F0rmat→Format,
and so on."**

What changed: names only. The ROM's bytes keep their zeros: every `.ascii` / `text=` literal, and every comment that
quotes a caption, still has 0x30 where the ROM has it. `make gate-wsa1` (byte-identical) and the ELF symbol proof
below show that nothing else moved.

## How a zero was decided

`inventory.py` reads identifiers from code only. It strips `;` comments and string literals first, because a
quotation of the ROM keeps its zero. A zero is the letter O when it sits inside one of 32 WORD TOKENS at a
CamelCase boundary, for example `C0py` in `MeasureC0py_Field`, `0pti0n` in `L0ad0pti0n` and `0utput` in
`Input0utput`. For each token, `inventory.md` gives its upper-case form searched in the four committed ROM images.
31 of the 32 occur there with 0x30. The 32nd, `C0mbination` with one zero, is the hand-made `L0adSingleC0mbination`
family; the ROM's own word is `C0MBINATI0N`.

Every other zero beside a letter is kept, with a reason:

- `HEX`: a digit of an address or hex value (`sub_F9FD0E`, `Msg0D`, `Rec0E3E`);
- `NUMBER`: a decimal number beside a word (`Part0Ctrl`, `Range0To100`, `Bit0to7`);
- `SFR`: a TMP95C061 register;
- `EXPLICIT`: one of ten cases where a word reading would see an O but the evidence says digit. Examples are the
  interrupt `INT0`, the floppy sizes `720K` / `1440K`, flash bank `S0` of `"WSA SOUND RAM S0" .. "S3"`, the float
  constants' `em05`, and the frequency table `DLBTable_12k16k20k...` (whose own text is "1.2k" "1.6k" "2.0k").

A second, independent method cross-checks the first: a dictionary reading of every zero (`/usr/share/dict/words`
plus a few domain words). It must find nothing outside the tokens except the EXPLICIT cases, or the script fails.
At the base it found nothing.

**One collision, resolved from evidence.** `DL_MidiFileSaveFileSelecti0n` (0xF59222) would become
`DL_MidiFileSaveFileSelection`. That name already belongs to 0xF58A62, which draws the same title spelled with O.
The two lists are pages 1 and 0 of MIDI FILE SAVE. 0xF59222 goes on to draw "FROM S0NG NUMBER :", so the tree's
title rule names it from the next literal, as it does whenever a name collides (`prom_a_dl_text_names.py`,
`prom_b_dl_screens_round5.py`). Its name is `DL_MidiFileSaveFileSelectionFromSongNumber`.

## What was changed, and what was left

- The code: `scripts/renaming/rename_wsa1_zero_for_o.sed`, one word-bounded rule per old name (block 1, 992 rules)
  and per block-2 word (51 rules), applied with `LC_ALL=C sed -i -f` to every file that quotes one. History files
  were excluded; they are listed below.
- The generators that build names from captions read the caption through `caption_o_for_zero.o_for_zero()` first:
  `gen_prom_b_f067a6_module.py --dl-names`, `gen_prom_b_f17559_module.py`, `prom_a_dl_text_names.py`,
  `prom_b_dl_screens_round5.py`, `prom_b_screens_round8.py`, `prom_b_entrypoints_round7.py` and
  `prom_a_understanding_round7.py`. The morpheme guards of rounds 5 and 7 compare a name with the ROM text read the
  same way; without that change, a name that spells `Load` would no longer match a caption typed `L0AD`.
  `scripts/tools/name_wsa1_ram.py` holds its names as data, and its `--check` passes against the renamed
  `include/wsa1_ram.inc`. `docs/gui-menu-map.md` was regenerated (`make -C wsa1 gui-menu-map`).
- The 0x30 notes. The ring_put_block.s comment now says that its warning still holds for the captions, and that
  label names spell O since 2026-11-06. `FINDINGS-prom_b-disk-and-file-menus.md` says the same. Each of the 12 source
  files that define a caption typed with 0x30 now opens with a note that names its words.
- The preservation declarations: `notes/prom_ab_names_zero_for_o.py`, imported by both checkers.
  `prom_a_preservation_check.py` now follows a chain of declarations (`sub_FF4986` → `ScreenLeave_DiskL0adFile` →
  `ScreenLeave_DiskLoadFile`). `prom_b_naming_preservation.py` already did.
- The dated notes that argued for keeping the zero (`notes/open6-kn5000-d/wsa1/README.md` lead 6 and open
  questions, `notes/open4-kn5000-b/naming/README.md`, rounds 5, 7 and 8) keep the old name, with the new one beside
  it on the same line. `--check` enforces that pairing.
- Tracker: kn5000-wxn gets comment 313. The comment says lead 6's "keep" verdict is superseded. The description,
  as filed, is unchanged.
