Traced in v10 (lane kn5000-d, sub-lane accomp, 2026-11-02). Notes: notes/open6-kn5000-d/accomp/README.md section B.

SYNCHRO & BREAK button: PanelButton_SynchroBreak (0xFC5B91) posts the 0x48/5 bit-1 switch event (not in modes 16, 19); AccStyleCtl_SynchroButton (0xF59CD9) toggles PANEL_STYLE+5 bit 1 in every transport state. There is no separate BREAK action. The chord keys do the rest (AccAutoPlay_*, per key event from NoteOn_EntryPoint): AccAutoPlay_SetConfig makes 0x346D bit 7 "synchro allowed" (SYNCHRO lit, AUTO PLAY CHORD mode on, no song recording/playing). First chord-zone key while stopped -> AccAutoPlay_Configure / _SubModeA -> AccAutoPlay_ActionDispatch -> AccPlayMode_StartAccPlayFull (synchro start, from the top). All chord-zone keys released (count 0x349C reaches 0) while running -> AccAutoPlay_SeqHandoff -> AccPlayMode_StopToSync2: PLAY and ACC transports = 12, stop at the next 24-tick boundary (synchro stop = the break); the next chord restarts; a chord within the stopping window cancels the stop (SubModeA clears bit 3). SYNCHRO is cleared only by the button and by AccAutoPlay_Disable (when a song track plays/records), so it stays lit after a synchro start and the synchro stop stays active.

End of an ENDING: AccVoice_HandleMarker83 parks an ending lane at its 0x83 marker (AccVoice_ActivatePart, 0x332A) instead of looping; all six parked -> 0x3283 bit 2 -> AccTick_Main runs AccState_CollectAll (0xF591D1) each tick, which waits until no note of the six sounding-note tables has bit 7 set, then stops (AccPlayMode_StopToSync2, or AccPlayMode_StartPlay2 = accompaniment only while a song plays), sends all notes off, restores the chord display, clears the ENDING LEDs, 0x3283 bit 2 and all section lanes. (0x3284 bit 2 is indeed not it.)

Correction: accvar README section 6's "ACC_TRANSPORT_STATE 128/134 while waiting" is the sequencer's start (0x28B2 bit 1, AccPlayMode_StartPlayFull / _StopExprB), not the chord synchro start; marked there.
