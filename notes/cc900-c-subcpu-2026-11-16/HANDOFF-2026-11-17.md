## Idioms (V4.23 at -Xr, no -O); details in README

- Reload after store: a second plain local takes the value, the kept local is assigned from it, the next uses
  read the second one.
- Constant argument loaded in argument order: the constant through a local; a constant pointer through a
  register local set before the call.
- Char argument unextended: the callee's parameter declared plain `char`, the argument uncast.
- A result kept in a parameter's register: reuse the parameter (`tbl = f(tbl, ...)`).
- Stack arguments are pushed left to right: the last parameter has the lowest (xsp+N) offset.
- An `int` passed to an `unsigned int` parameter is loaded before a push; the ROM's order needs matching types.
- Operand order decides evaluation order; a switch's compares come out in reverse source order; switch bodies in
  the ROM's order.
- Doubling by add is `w + w` on a local; `* 2` / `<< 1` give a shift.
- Declaration order matters for some pairs of temporaries (a byte local before a pointer local).
- A constant times a loop register (`ld wa,K; muls xwa,iz`) is a comma expression (lane_hd).
- A switch over several labels is one C function; check with `span_refs.py` (its own case table excluded).
- Floating point: a register-convention function may not return float / double (THC1-Error-373 "Illegal function
  return type"); `__cdecl` ones may.  Arithmetic and conversions are plain operators.

The ROM's callers pass addresses for arithmetic (XWA destination, XBC left operand, XDE right) and push doubles
plus a result pointer for pow / sin / cos / tan (caller pops).  `helper-generators/fpconst.py` prints every FP
constant of the payload with a C literal giving its exact bits (`fpconst.txt`).  Two equal constants are two
objects (V4.23 does not merge them): DSP_AlgoParam_Decode has FPConst_DSP_AlgoParam_Decode_0p552 and
FP_Const_0p552_Add.

The 14 FP functions (pool E) and the FP_* labels each calls are in helper AC's table, copied here:
DSP_AlgoParam_Decode, DSP_MixerCoeff_Compute, DSP_ReverbCurve_FP, DSP_ParamInterp_FPComplex, DSP_SOS_LUT_Fetch,
DSP_VolumeCurve_FP, DSP_DetuneCurve_SignedFP, DSP_BiquadWarp_FP, DSP_FilterLUT_Fetch, DSP_ParamEQ_Curve_FP,
DSP_SOS_Coeff_Compute, DSP_BiquadCoeff_Compute (FP_cos and FP_ddiv in the pool are library routines).
Helper AC's plans: DSP_AlgoParam_Decode is `long (unsigned char **pp, unsigned long x)` with
`r = (double)f * 0.552`; DSP_MixerCoeff_Compute is `void (unsigned int a, unsigned int b, unsigned int c)` with
DSP2_MixerGain_Curve a `long __near` array; the two LUT fetches are a switch on `*p & 0xf` holding a switch on
`*p++ & 0xf0`, gains `tbl[i] * 0.5 + -12.0`.  Open: how V4.23 lays out FP temporaries in the frame.
