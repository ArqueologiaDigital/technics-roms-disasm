## What was fixed today

1. **Older HD-AE5000 trees were compared with the v2.06i image.**  `tree_of()` mapped every `hdae5000*` source to
   `hdae5000`, so the ported C of `hdae5000_v2_01i/`, `hdae5000_v1_15i/`, `hdae5000_v1_10i/` (per-tree sources from
   2026-11-16 on, 20 runs, 1,666 rows by `probes/drop_runs.py --list-misattributed`) was linked at v2.06i addresses
   and compared with the v2.06i ROM.  Where the code is the same it MATCHed there, so `ready.tsv` listed v2.06i rows
   that lane_hd had already built (lane_hd's report on hd-r61).  Fixed: the three trees are in `TREES`, `ELF_OF` and
   `LANES` (their ROMs are git-ignored; `rom_path()` reads the main checkout's copies).  The 20 runs were taken out
   with `drop_runs.py --misattributed` and indexed again by `--add-new`.  Check (`probes/nonerr_same.py acfcc6c05
   --reindexed-hd`): every non-error row outside those runs is byte-identical (MATCH 22,746, NEAR 10,746, DIFF
   12,952; none changed); the rows of their v2.06i sources are all unchanged; the re-attributed rows moved as listed
   by the script (most stay MATCH on their own tree; some MATCH -> NEAR / DIFF / ERR-name, where the older image
   differs); 40 old rows of those runs have no partner (ERR-dup / variant rows paired differently).
2. **K&R definitions were not seen as definitions** (`c_defs_text`).  lane_hd's lyrics C defines functions K&R style
   (`long f(pos) long pos; {`), which the build's `c_functions` reads but the index's copy did not, so functions main
   builds were listed in `ready.tsv` as not built (the 5 `hdae5000` rows of hd-r59 and 3 of `hdae5000_v2_01i`, among
   18 in all).  `c_defs_text` now uses the build's pattern; `selftest.py` has a case for it.  It also serves C
   provenance (`find_source`: a C file that defines exactly the listing's functions), so a K&R file is now found by
   name too.
3. New checks in `probes/`: `nonerr_same.py` (no damage to rows a pass did not select), `per_tree.py`,
   `ready_summary.py` (writes `ready-by-lane.md`), `drop_runs.py`, `orphan_copies.py`; `status_moves.py` takes an
   index.tsv path as well as a rev.

`--add-new` took 22 minutes for 95 runs (4,229 listings) with `--jobs 2`.  To wait for a pass, run it as a background
command and wait for its exit; do not loop on `pgrep -f <its own pattern>` (the waiting shell matches itself and the
loop never ends).
