0xc598 AUDIO_SEQ_TRACK_FLAGS ; word: what the sequencer's tracks ask of the voice routing, rebuilt from 0 by Audio_CheckInitStatus (audio/audioinit_routines.s) over the 16 tracks.  A play track is one in SEQ_TRACK_MASK | 0x0d51, a record track one in SEQ_REC_TRACKS | 0x0d4f (the step and beat / drum editors' own masks: SqStep_SetupCursorTrack sets the cursor track in both, BmDrEdit_InitCommon_SetupDisplay copies 0x2963 into both); a track counts only when its TRACK ASSIGN (SEQ_TRACK_ASSIGN) has an AudioInit_SlotOrderMap entry (CONTROL 15 has none).  bit 0 = exactly one record track (its slot is then AUDIO_REC_TRACK_SLOT, which AudioInit_ConfigureVoiceFromFlags copies to 0xc1ff); bit 1 = a record track is CHORD (TRACK ASSIGN 13); bit 2 = a record track is APC (14); bit 3 = a record track is RHYTHM (16); bit 5 = a play track is CHORD; bit 6 = a play track is APC (the AUTO PLAY CHORD recognizer is then taken from PANEL_STYLE+4, see AUDIO_CONFIG_FLAGS); bit 8 = there are play tracks; bit 9 = there are record tracks (cleared again while 0x28b3 bit 3 is set), tested by 15 voice-allocation routines of note_voice_mapping.s and by Audio_InitDispatchReturn; bits 4, 7 and 10-15 are never set
0xc59a AUDIO_VOICE_CHANGES ; word: the second change mask of AudioInit_DispatchChanges (beside AUDIO_STATE_CHANGES), cleared by it after the send: bit 9 = run AudioInit_CompareVoiceConfig (set by the AudioInit_*Routing / AudioInit_UpdateVoiceBank* / AudioInit_ClearBank*Routing routines); bits 12-14 = run AudioInit_ComparePriorityTable; bit 13 (unless AUDIO_CONFIG_FLAGS bit 4) and bit 12 = re-allocate the tone (Voice_UpdatePlayModeState, VoiceEvent_AllocAllLayers), bit 13 set by PanelTag48_UpdateAudioConfig_ApcMode; bit 14 = NoteMap_FindBestMatch then VoiceEvent_DispatchTable, set by PanelTag70_UpdateAudioConfig and UIStateEvt_ParamEdit_Data case 4; bit 2 (UIStateEvt_TransposeUpdate_Apply, UIStateEvt_VolumeMixer_Data) and bit 10 (PanelTag70_UpdateAudioConfig) are set but read by nothing; no code sets bit 12
0xc59c AUDIO_STATE_CHANGES ; word: which parts of the audio state AudioInit_DispatchChanges compares and sends -- the state is the 358 bytes at 0xc1fe, which it then copies (ldirw, 0xb3 words) over their sent copy at 0xc364, and clears this word.  Bit 0 (and bits 1 / 8) = AudioInit_CompareVoiceConfig; bit 2 = AudioInit_ComparePartAssignment (set by Tone_WriteEndMarker and, with bit 8, by AudioInit_Routing_Done and the AudioInit_Check*Bit5_FBF1 ends); bit 3 = AudioInit_ComparePartConfig, and with bits 7 / 8 AudioInit_ComparePartStates (bit 3 set by the PanelTag80_UpdateAudioConfig arms, AudioInit_ClearPartFlags_Loop, UIStateEvt_DrumAssign_Notify); bit 4 = AudioInit_CompareVolumeTable (set by AudioInit_SelectPriority and the AudioInit_Priority_* arms); bit 6 = AudioInit_CompareChannelConfig, and with bits 7 / 8 AudioInit_CompareChannelMappings (bits 6 / 7 set by Audio_CheckInitStatus's track loop); bit 8 = AudioInit_ComparePriorityTable; bit 5 (AudioInit_CheckMIDIStatus) and bit 11 (UIStateEvt_VoiceAssign_Notify) are set but AudioInit_DispatchChanges does not read them
0xc59e AUDIO_REC_TRACK_SLOT ; the AudioInit_SlotOrderMap entry of the first record track Audio_CheckInitStatus meets (0xff = none; set to 0xff before the track loop); with exactly one record track (AUDIO_SEQ_TRACK_FLAGS bit 0) AudioInit_ConfigureVoiceFromFlags copies it to 0xc1ff
