0x32f4 ACC_PART_FLAGS ; state of the working accompaniment part (sequencer/accompaniment_engine.s, rhythm_routines.s): bit 0 = skip it this tick: its next event is more than 24 ticks ahead (AccKbd1_TimingCheck and the AccSeq_* scanners) or it has ended (AccPart_Deactivate_SetDone, AccVoice_ParkLaneAtEnd), tested by the AccKbd* / AccCh* _ProcessNotes, cleared by the _SaveState routines; bit 1 = bar end reached in range (AccSeq_EndOfBar_Process, AccVoice_BarEnd_InRange; AccVoice_HandleBarEndEvent tests it); bit 2 = the part is ACCOMP1 (part 8) and bit 3 = BASS (part 4), set by AccCh2_NoteOnEntry / AccCh1_NoteOnEntry and the Rhythm_DispatchCh_* / Rhythm_SetupChannel_* routines, select the chord-row variant and the bass rules; bit 4 = fixed note, not converted (Rhythm_CheckFixedNote); bit 5 = the lane reader skipped too many unknown bytes (AccVoice_AdvanceAndCheckEnd), AccTick_AfterSync then stops; bit 6 = the pattern scanner met an unknown byte (AccSeq_Scanner_Unknown), AccTick_Main returns early; Seq_DispatcherTick_Process clears bits 5 and 6
0x332c ACC_LANES_RESYNC ; bits 0-5, one per lane in ACC_PART_BIT order: the lane's part sound was (re)loaded (AccPart_LoadTuning*, AccPart_ResetAndCopyTuning and the section starts AccSection_* set them); AccVoice_DispatchByChannel runs the lane's AccKbd* / AccCh* _ProcessNotes only while its bit is set, and that routine clears it after re-timing the sounding notes and ring buffer and sending the part's sound record (RhythmPartN_LoadAndStore); bit 7 = reload every part: AccTick_Main runs Rhythm_ProcessAllPartsAndLoad and clears it (set by AccSection_ApplyPendingChange, AccSection_SwitchNow_SetDirty, AccTick_ByteData, AccTuning_ApplyVoice)
