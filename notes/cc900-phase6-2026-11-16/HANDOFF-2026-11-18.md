## Tools changed or added (all committed, each with a check)

- `model/to_llvm.py`: `OP (Xrr+Qrr),#` for ld / cp / add / adc / sub / sbc / and / xor / or, byte and word, and
  inc / dec word (`qidx_imm`).  Backend raw pseudos where they exist, else the bytes; checked by
  `model/test_to_llvm_qidx.py` (17 translations, the `.byte` forms read back with MAME's unidasm).  Unblocked
  `Sprintf_FormatGGeneral`'s translation (it now differs at +39, a C question).
- `asm_vs_rom.py`: `place_locals()` gives an absolute operand naming the function's own label (a switch base,
  `lda xix,(L:24)`) the label's ROM address; the same test checks it.  Unblocked the ParaLoadOpt pair (built since
  52656a52a) and every later switch whose base is a code label of the function (GetVolumeLabel, FDC_CONFIG_VERIFY).
- `stage_probe.py` / `restage_modules.py` / `port_staged.py`: a function's `cc900-data:` comment travels with it
  (`stage_probe.names_fn`); before that, staged switch functions could not be translated in the per-tree check.
- `port_staged.py --keep-unproven`: keeps a function whose v10 / tree bytes differ outside the C's address fields
  (relative calls to moved callees, own switch bases); V4.23's per-tree check decides.  The "no function left" line
  names the drops.
- `promote_staged.py`: a staged prototype of a function the built file DEFINES counts as a conflicting
  declaration, so the staged C goes to a sibling file (V4.23 refused `dsp_config_sysex_m293.c` with THC1-Error-262
  after an append put `extern int DSPCfg_GetSlotCount(int);` below its `unsigned int ...(unsigned int)` definition;
  the staged functions had been checked against their own prototype).  `fix_c_comment.py` then pointed the three
  label comments at `dsp_config_sysex_m293_b.c`.
- `ready_check.py`: which lane_p6 rows of the near-miss `ready.tsv` are really new (196 of 198 were already built).
- `promoted_bytes.py RUN`: functions / bytes a promotion built per tree, from `staged_v423.tsv`.

## Helpers

Three helpers (I, J, K) worked fresh pools made by `new_pool.py ~/compartilhado/tmp/cc900-tab/lane_p6/scan/pool18_
I J K --min 60 --max 900` (2,187 routines, about 415 KB not tried by anyone before), with the brief
`~/compartilhado/tmp/cc900-tab/lane_p6/scan/BRIEF-2026-11-18.md` (scratch; it points to the rules file and the older
briefs).  What they found worth keeping:
- The draw-queue family of module 273 (`DrawLine`, `DrawBox`, ... `UpdateScreen`: a direct draw when
  `IS_XSP_INSIDE_4K_REGION_AT_1C032` and `DRAW_ENABLED`, else a `DrawQueue_Alloc` entry posted by `DrawRing_Post`)
  is plain V4.23 -O3 -Xr C: 18 wrappers and their queued stubs matched in one round, `DrawString` with its firmware
  bug (it passes the uninitialised command pointer's string field) included.
- `return ram_7f48;` after `ram_7f48 = K;` is folded to the constant at every set; the ROM's reload comes from a
  `volatile` cell (FileIO_OpenWithMode, run r36).
- A pointer argument spelled `0x8094L` gives the ROM's `ld xR,N`; `(long)ram_8094` gives `lda`
  (SmfSeqToSongNumFunc, run r36).
- Most large entries of the pools that remain are hand assembly (bank registers, Q-register byte code, args in
  XIY, labels inside instructions); the helpers' skip lists are in their reports (scratch).
