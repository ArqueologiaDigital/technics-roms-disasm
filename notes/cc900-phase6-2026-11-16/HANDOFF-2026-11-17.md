## Idioms found (how to make V4.23 write the ROM's code)

- Operand width comes from the declaration: plain extern = 24-bit, `__near` = 16-bit, `__tiny` = 8-bit; one object
  per qualified declaration (only the first declarator is qualified).
- Option sets: the firmware's -O files are `-O3 -Xr`, files without -O `-Xr`, sprintf_core `-O3 -XS -Xr`.  A plain
  `-O -Xr` set gave nothing new (run 2026-11-16-128).
- Module-local calls (`calr` / `jr` / `jrl`) need the callee in a `cc900-module:` line (module_calls.py prints it).
- Memory-to-memory moves come from `__near` cells; `volatile` on the cell makes V4.23 load + store instead.
- Stack arguments of non-__cdecl calls are pushed left to right: the last parameter has the lowest offset.
- Frame slots: plain scalars never address-taken take the lowest slots in declaration order; address-taken locals
  sit above them in reverse declaration order (both readings produced matches, run 2026-11-16-123).
- A no-code `&param;` keeps a parameter in the frame (`volatile` does not), but it also makes V4.23 load it early.
- A local copy of a parameter beats the parameter for the XIZ home.
- `x & y`: V4.23 puts the right operand in the register; switch compares run last case first; a default written
  last that falls into the tail moves right after the compare chain.
- V4.23 emits conditional calls (`cal cc`) itself.
- lane_sub's spellings: reload-after-store via a second plain local; a constant argument through a local; a char
  argument without extz via a plain `char` parameter.
- lane_hd's: a converted pointer (`(T *)(long)x`) loads its base with ld immediate; `(0, K) * i` gives
  `ld wa,K; muls xwa,reg` in the ROM's order (-Xr).
- A 16-bit table index: subscript a SIZED array with the cell directly (`tab8[cell]`).
- Do not index constant struct pointers with whole-element copies: V4.23 crashes (bug 11, `cc900-v423-bugs.md`).
- Struct arrays are padded to even offsets; odd-sized members misplace everything after them.
