# kn5000-nl6: the naming leads of 2026-10-06/07, checked (lane open4/kn5000-b-naming, 2026-10-31)

The tracker issue `kn5000-nl6` collects leads the read-only naming agents of 2026-10-06 and 2026-10-07 reported
and did not act on: suspected mislabels, data spelled as code, stale comments, a tool bug.  Each lead below was
checked against the code before anything was renamed; the verdict says what was done.  Leads that belong to the
other kn5000-b sub-lanes (control panel, MIDI, engine, HD-AE5000) are marked so and were not touched here.

## How the changes were made (reproducible)

- `scripts/renaming/rename_open4_naming.sed` -- every rename, one rule per line with the reason above it,
  applied with sed to the `.s`, `.c`, `.ld` and `.h` files of v10 / v9 / v7 / v6 / v5 (v8 is v9's source).
- `scripts/renaming/open4_naming_patches.py` -- the edits a sed line cannot make: headers, stale comments,
  duplicate-label merges, data respellings and the six new labels.  Its docstring gives the order
  (`--pre`, the sed, `--post`; `--v142` for the sub-CPU payload, after which
  `scripts/generators/create_v141_subcpu_source.py` and `create_v140_subcpu_source.py` regenerate v1.41 and
  v1.40).  Every edit is an exact text replacement that reports per tree.
- The four welcome-glyph PNGs were renamed with `git mv` in every tree; `scripts/build/c_bitmaps.py` and
  `scripts/build/convert_images.py` follow the new names.
- WSA1: `wsa1/prom_b/modules/f6f000_f7a3ff_smf_file_io_and_old_copy.s` (one routine) and
  `wsa1/notes/wsa1_exact_copy_names.py` (its older-build range).
- `scripts/tools/frame_switch_cases.py`: the multi-range bias fix.

Nothing changes a ROM byte: `make gate` and `make gate-wsa1` pass (gate line at the end), and the symbol files
were regenerated with `python3 scripts/analysis/l2_symbol_reference.py --regen` (`--check` PASS).

## Website page draft

The technics-docs pages that need text changes (the docs lane applies them; this lane does not edit
technics-docs).

**cpu-subsystem.md**, the port-bit table, row PE.4: replace "a change sends an 8-byte packet on the
computer-interface port" with:

    | PE.4 | input | MICSNS -- latched every main loop; a change is sent to the sub CPU as global sub-command 0x08 of command 0x2C (sub-CPU `DSP_Set_MicSense`) |

**dsp-effect-data-zone.md**, "Settled translator-opcode semantics": the two rows are one opcode high.  The
sub-CPU dispatch (`DSP_Translator_CaseOffsets`, index = opcode - 0x61) gives index 6 = `DSP_Op_0x67_InterpFPScale`
and index 7 = `DSP_Op_0x68_InterpDiv0xB4`:

    | `0x67` | ms x 44100 / 1000 + base -> DRAM word count (delay times; the 44.1 kHz rate is hard-coded) |
    | `0x68` | value / 180 -> degrees (PHASE / PAN family) |

(the rows for 0x21, 0x62, 0x63, 0x70 agree with the dispatch; 0x6D and 0x72 were not re-checked here).

**dsp-bytecode-interpreter.md**: in the Level 2 table, row 0x67's Purpose becomes "ms x 44100 / 1000 + base ->
DRAM word count (WriteOscParam_Offset)", row 0x68's "value / 180 (0xB4) -> degrees"; in the paragraph at line 148
"`0x68` ms->DRAM" becomes "`0x67` ms->DRAM".
