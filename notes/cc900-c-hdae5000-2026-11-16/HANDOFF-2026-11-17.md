## Idioms found (V4.23 at `-Xr`, without `-O`)

The full list is in `helper_brief.md`, sections "What is known", "More idioms found since" and "Idioms found in run
2026-11-17-3-hd-r36", and in the README's "C idioms" section.  These were found since, in runs hd-r39 to hd-r47:

- **The reload after a store** is avoided with `n <<= 4; size = n;` (LoadSong_Cmp / _Msp / _Sqt).
- **Keeping a parameter in IZ:**
  - copy it to a local declared before the result (`d = dir`, PPORT Svc13);
  - a no-code use `(void)&x;` keeps a parameter out of a register, so that the other one gets IZ (FlsItem_Get,
    FlsItem_SongRecord).
- **Freeing WA as the work register:** a local copy of the first parameter (FlsItem_Set, Lbn_StepDigit).
- **Argument loading:**
  - unsigned cells passed through `int` names load after a push (LBNPage1SwCatch);
  - a format string as an `extern char[]` passed unconverted is pushed as two words; a converted one goes through
    XWA first (Separate*Check).
- **Arithmetic:**
  - a 16-bit add is kept in an index by `(int)((unsigned int)n + K)` (FdList_Scan);
  - a signed int product converted to long before pointer scaling: `p += (long)(bank * 1024)` (LoadSong_Sqt).
- **A function's result tested signed in HL** without a reload: through a second local,
  `l = f(..); len = l; if (l > 39)` (Lyrics_PlayToPosition).
- **A two-level switch** (byte map plus offset table) comes when the C has a case for every key in the map's range,
  even empty ones.  Both tables are named with `cc900-data: F 1 = Map` and `cc900-data: F 2 = Table`
  (FDFileSelectProc).
- **Char parameters:** prototype-style definitions with `int` parameters and an `(unsigned char)` cast inside replace
  the K&R definitions (Lyrics_FillLines, Lyrics_ParseEvent); an `unsigned char` parameter where the ROM stores and
  compares only the byte (PlayToPosition).
- **Calling a function under a short C name:** call it by its tree name when its first 31 characters are unique.
  `hd_v423.py` maps a `cc900-name:` line only for functions the file defines (see blockers).

## Known blockers and who owns them

- **`hd_v423.py --check` and called-only short names** (owner: lane_hd, `hd_v423.py`).  It does not map a
  `cc900-name:` line for a function the file only calls, and reports "cannot resolve 'no address for .Short'".
  Work-around: call the function by its tree name.
- **`hd_v423.py --show` on some old runs** (owner: lane_hd).  It stops with `KeyError: no address for .Short` or
  `S1`.  A read-out of such a run must use the run's listing or `--check`.
- **ERR-translate rows in the near-miss index** (owner: lane_nmx / lane_vmb).  Some functions are recorded as
  ERR-translate when a string label longer than 30 characters is cut in the listing.
- **The V4.23 cache before the splice** (owner: built into `promote_hd.py`; the build side is lane_vmb's).  The cache
  must hold a C file with `cc900-data:` before the splice: run `promote_hd.py --keep-uncached`, build the tree, rerun.

## How to resume

1. Merge main into `cc900/c-hdae5000`, `make -j2 gate`.
2. Pick an open function.
   - `remaining.py` lists them.
   - Its best attempt and that run's code: the near-miss index, then
     `hd_v423.py --show RUN CNAME 2>/dev/null` against `survey.py --body LABEL --comments`.
   - For SelectListProc, `selectlist/cmp.py` does the instruction-level comparison and `selectlist/gen.py` writes the
     next probe (`selectlist/README.md`).
3. Write forms as `probes/hd_rNN_*.c` and commit them before the run.  Build the corpus with
   `hd_v423.py --corpus $TMPDIR/cc900-tab/lane_hd/rNN Xr FILES` and run
   `bash scripts/analysis/cc900/oracle/run_oracle.sh hd-rNN CORPUS CORPUS/sources.txt CORPUS/options.txt v423`, one
   VM job at a time.  Then check with `hd_v423.py --check RUN --calr`.
4. For each match:
   - `stage_from_probe.py PROBE hdae5000/cc900-staged/NAME.c "WHAT" FUNC...`, commit;
   - staged run, then `hd_v423.py --check RUN --record`;
   - `port_staged.py RUN`, ports run, then `--check RUN --dir TREE --image IMG --record`.
5. Promote:
   - `promote_hd.py --keep-uncached`; if it reports UNCACHED, build the image and rerun it;
   - `make -j2 gate`; if a menu map is STALE, regenerate it with `scripts/analysis/hdae5000_menu_map.py` and compare
     with `menu_map_diff.py OLD NEW`: 0 dropped is required;
   - `git rm` the staged files that `staged_done.py` reports complete;
   - commit with the counts.

Every commit message ends with the LLVM line, a blank line, the Co-Authored-By line of the session's model and the
Claude-Session line.
