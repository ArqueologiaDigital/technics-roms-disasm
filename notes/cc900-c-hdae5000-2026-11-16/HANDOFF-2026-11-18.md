## Open functions, with their best attempt

- **`SelectListProc`** (2,641 B).  Best: `probes/hd_r55_sl.c` forms t / v / w (run -20-hd-r55): the ROM's code
  but for ONE instruction at nine places: after `ld (xsp+4),xhl` (the view pointer stored to v) the ROM copies the
  register, `ld xwa,xhl`, where V4.23 reloads v from the stack, `ld xwa,(xsp+4)`.  Item 3 (registers) is settled
  (declared t, a, col); the register local u (long, `u = GETVIEWL(obj); v = (T)u;`) is what puts the function
  pointer in XIX.  Tried without success: u used as the first operand (pointer cast: `(xhl+N)` straight; integer:
  `add xhl,N`), the store as an assignment operand (`V_x((v = (T)u))`, run hd-r57), -O1 / -O2 (run hd-r58-opts:
  2,545 B, further from the ROM).
- **`DbMemoClProc`** (487 B).  Best: `probes/hd_r55_pp.c` DbMemo_h (run -24-hd-r56): exactly the same single
  difference as SelectListProc, twice.  Whatever gives SelectListProc's copy gives this one.
- **`FlsItem_Insert`** (384 B).  The ROM has i in IY, the destination in XIZ, the record offsets built in XIX.
  (i, a): i IY, a XIX (FlsIns_j); an offset local o gives the ROM's 384 B but i HL / o XIZ / a XIX (hd_r51_fi.c);
  a pointer a, `register`: no change (hd_r52_fi.c).  Unused locals take no register.
- **`FormatDialog_CodeDigit`** (136 B).  Best: `probes/hd_r52_cd.c` / `hd_r54_cd.c` CodeDigit_q (`register unsigned
  char *p;` declared before `int i;`, `i = (unsigned int)ram[0]; i += 2; p = ram_22ad9c; p[i] = ..`): one
  difference, p's assignment `lda xwa,ram; ld xde,xwa` where the ROM has `lda xde,ram`.  Learned: the cast to
  `unsigned int` widens in WA (the ROM's `extz wa; ld bc,wa`); a pointer local declared before i moves i to BC.
- **`FILE_Naming_Screen`** (46 B) and **`LyricJumpEditCheck_Unregistered`** (87 B): the ROM keeps a compare and a
  conditional jump to the very next instruction (`cp xhl,11; jr z` / `or xhl,xhl; jr z`).  Helper h_misc scanned
  the 10,578 V4.23 listings in the oracle runs (script `h_misc/jnext.py`, harvested to research-scratch): no
  conditional jump to the next line anywhere, every option set.  So V4.23 removes such a jump with its test, and
  plain C cannot give these two; an `__ASM` body is the only idea, untried.
- **`PPI_LoopbackByte`** (130 B), **`ENTRY_1`** (vector jump and padding), **`Clear_Work_Buffer`** (start-up clear
  and data copy with djnz loops), **`Lyrics_WriteVarLen`** (djnz16, never seen from V4.23 at -Xr): hand assembly.
- `NameHistory_AfterPushNop`, `Finalize_Init` (1 B each): a lone `ret`, not worth a probe.

## Idioms found today (V4.23 at `-Xr`)

- **A switch's dense table needs its holes as empty cases**: FILE_LOAD_Screen's six cases over a range of 14 gave a
  compare chain until the eight missing values were written as empty cases (they share the end).
- **`cc900-data:` numbering of nested switches**: the INNER switch's table is V4.23's first f_const object
  (LyricBoxProc: `1 = _CaseTable2`, `2 = _CaseTable1`).
- **MAX / MIN of the edit checks**: `?:` with a constant false arm loads it before the test; the ROM's shape is
  statements on a long local, `if (pos == 5) { r = N; if (flag == 0) r = 0; } else r = 0; return r;` (LBN*).
- **A pushed / register argument that the ROM routes through WA or XWA is a CONVERTED one**: the part mask passed
  `(int)` (Sfx* / LBN*), the text pointer `unsigned char *str` passed `(char *)str` (AcLanguageText1Proc).
- **The GET_STR_PTR / GetViewInstance call's function pointer goes to XIX** when its result is assigned to a
  register local held in XHL (a long local, converted afterwards); otherwise it is called through XHL.
- **Arguments loaded before the pushes, straight into XHL / XBC**: member addresses of RAM declared as structures
  (`&ram_22a088.box`, LyricBoxProc); plain variable addresses are loaded after the pushes.
- **An argument copied into a local at the start of one switch arm** (not in the prologue): copy it there
  explicitly (`p = arg;`, the name checks).
- **Stack arguments are pushed right to left as written**: RegisterTitle's arguments had to be written in the
  order the ROM pushes them reversed (Handler_Registration, run hd-r58).
- `i = (unsigned int)uc;` into an int local widens in WA and copies (`extz wa; ld bc,wa`); `i = uc;` widens in place.
