## What moved the older trees

The older trees' C failed where v2.06i's C wrote a v2.06i number, and most of those numbers were not in the C:

1. **Object ids.**  Each older tree's `cc900/hdae_ids.h` was a copy of v2.06i's.  It is now `gen_ids_header.py`'s
   output for the tree's own ELF.  v2.01i's `Frame_Handler` names its object 0x7f013e by v2.01i's name
   (`OBJ_FLS_FILE_LOAD_AcIndexEditSw`); its menu-map credit moved there (v2.06i's `FLS_FILE_LOAD_SW_EDIT` is the same id,
   v2.01i's is 0x7f0140).  Run 2026-11-19-14-hd-r61-ids-ports; staged run -17-hd-r62-ports-staged; +62 / +41 / +41.
2. **`ram_<hex>` cells** (RAM cells, and strings whose labels exceed cc900's 31 characters):
   `port_built.py --remap` moves each to the older tree's address of the label at that v2.06i address, else the
   nearest label below plus the distance.  Run -23-hd-r63-remap-ports; staged run -26-hd-r64-staged; +52 / +29 / +29.
3. `PPORT_Svc18_RequestNormalMode` (v2.06i, 32 B): it matched in run 2026-11-16-116-hd-r27c and was never staged;
   promoted with run -26-hd-r64-staged.  (V4.23 ends a void function whose last statement is a call through a
   pointer with `jp (xhl)`.)
4. **v1.15i / v1.10i event codes.**  These trees have their own `shared/event_codes.s` (v1.10i reads v1.15i's; v1.x
   numbers some HD-AE5000 messages differently: `EVT_HDAE_SET_STR_ADR` is 0x1ea0009 there, 0x1ea000a in v2.06i);
   `gen_ids_header.py` now reads the tree's own file.  Run -32-hd-r65-evt-ports; staged run -33-hd-r66-staged;
   +1 (Svc18) / +11 / +11.

5. **APFUNC ids.**  Some C files `#define APFUNC_<X>` numbers (0x12a00NN) that each version numbers differently;
   `port_built.py --remap` writes the tree's `NAKA_APFUNC_<X>` (from its ELF).  Run -39-hd-r67-apfunc-ports: +2 / +2.
6. **RAM cells no label reaches**: `learn_remap.py` reads the near-miss read-outs (`selectlist/cmp.py --image IMG`)
   into `learned_remap.tsv` (v2.01i 31 pairs, v1.15i 16, v1.10i 16), applied by `port_built.py --remap --extra`.
   Run -46-hd-r68-learned-ports; staged run -48-hd-r69-staged (with round 5's): +2 / +6 / +6.

7. **Per-tree C written from the older trees' hand source** (helpers h_v1parts, h_v1misc, h_v201; probes
   `probes/hd_r71m_*`, `hd_r72p_*`, `hd_r74v_*`, `hd_r75{a,b,c}_*`, `hd_r77_*`, `hd_r78_*`, compiled with
   `hd_v423.py --corpus DIR Xr --tree TREE`; staged as `<tree>/cc900-staged/*_rNN.c`, names no `cc900/` file has).
   Runs -59-hd-r71-v1misc, -60-hd-r72-v1parts, -62-hd-r74-v201, -63-hd-r75-v1fix, -66-hd-r77-writestream,
   -70-hd-r78-v201b; staged runs -61-hd-r73-staged, -64-hd-r76-staged, -72-hd-r79-staged (r78 doubled as the
   staged run of v1.10i's HD_WriteStream).  +11 / +28 / +28.  What decided the near misses:

## How to resume

As in `HANDOFF-2026-11-18.md` for v2.06i.  For the older trees:

1. `python3 -B notes/cc900-c-hdae5000-2026-11-16/port_built.py --layout OUT --remap` (OUT under `$TMPDIR`), then
   `hd_v423.py --corpus DIR Xr OUT/*/cc900-staged/*.c` and the oracle run.
2. `port_built.py RUN --remap` stages what matches; commit; a staged run (`hd_v423.py --corpus` over the staged files);
   `hd_v423.py --check RUN --dir TREE --image IMG --record` per tree.
3. `promote_hd.py --keep-uncached`; `make` the four HD-AE5000 images (fills the cache); `promote_hd.py --keep-uncached`
   again; menu maps (`scripts/analysis/hdae5000_menu_map.py`, `menu_map_diff.py`); `git rm` of what `staged_done.py`
   calls complete (and the header copies `port_built.py` put beside them); `make -j2 gate`.
