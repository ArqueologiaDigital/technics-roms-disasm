# KN7000 disassembly

A byte-exact disassembly project for the **Technics SX-KN7000** firmware.

The keyboard's main CPU is a **Panasonic MN10300/AM33** (it embeds the kernel
banner `MILK MN10300 Ver1.0R1`) — *not* the Toshiba TLCS-900 used by the KN5000.
The two flash images reverse-engineered here are produced by the sibling
[`kn7000_extraction`](../kn7000_extraction) repo from the original system-update
floppy disks:

* `kn7000_program.rom` — 0x3F6F01 bytes, main firmware, mapped at CPU `0x48400000`
* `kn7000_table.rom` — 0x3E94D4 bytes, resource archive, mapped at CPU `0x48000000`

## Goal: 100% byte-match

`make verify` reassembles the source in `src/` and checks that the result is
**byte-for-byte identical** to the original images:

```
$ make verify
OK    kn7000_program.rom is 100% byte-identical to the original
OK    kn7000_table.rom is 100% byte-identical to the original

All images reproduced byte-for-byte.
```

The project is already at 100% match — because it *starts* as a skeleton in
which every byte is pulled in verbatim (`.incbin_range`). Reverse engineering
then proceeds by replacing those raw ranges, region by region, with real
disassembled instructions and typed data — while `make verify` guarantees the
rebuilt image never drifts from the original. "Understood" bytes go up; the
byte-match invariant is held at 100% the whole way.

## Layout

```
src/program.s   MN10300 firmware image. Boot header is hand-disassembled;
                the rest is raw .incbin_range awaiting disassembly.
src/symbols.inc  2302 recovered function names + memory map (see "Symbols").
src/table.s     Resource archive: 85-entry offset directory + 84 asset segments.
src/picture.s   IC19, the picture ROM: a directory + the 100 Slide Show PRESET
                pictures, included from src/picture/preset_NN.jpg (see "IC19").
kn7000.sym      Portable "0xADDR  name" symbol table.
tools/kn7asm.py Self-contained assembler/linker (see "Toolchain" below).
tools/mn10300_asm.py      MN10300 instruction ENCODER (99.9% round-trip; see below).
tools/validate_asm.{py,sh} Round-trip the encoder against unidasm over the ROM.
tools/gen_symbols.py      Recover function names from the firmware's own tables.
tools/disasm_functions.py Named, function-by-function disassembly.
tools/dump_table_dir.py   Annotates the table directory.
disasm/         Reference disassembly listings (see below).
src/sp7001/     The SP7001 firmware (program 942 / table 83), GENERATED: see "SP7001".
kn7000_sp7001*.sym  Its symbols: ported from 941/84, plus names new in 942 / the plug-in.
baserom/        Reference images, regenerated by make (git-ignored).
build/          Reassembled output (git-ignored).
```

## Building

```
make            # build + verify (regenerates baserom/ from the disks if needed)
make verify     # assert 100% byte-match
make verify-listings  # byte-check + re-encode the curated disasm/*.asm listings
make symbols    # regenerate kn7000.sym + src/symbols.inc from the ROM
make disasm     # (re)generate disassembly listings (raw + named) via MAME unidasm
make verify-picture    # IC19 from src/picture.s + its 100 JPEGs: assert the instrument's SHA-1
make verify-sp7001     # SP7001 firmware (942 / 83) + BASEEXT.XAP: assert 100% byte-match
make verify-sp7001-floppy  # table 83 vs the SP7001 update's two table disks (+ SMCKTB*.INF)
make symbols-sp7001    # port the 941/84 symbols to 942/83 (+ the plug-in's own names)
make program-src-sp7001 table-src-sp7001   # regenerate src/sp7001/*.s (needs unidasm)
make clean      # remove build/
make distclean  # also remove regenerated baserom/ and listings
```

## Symbols — reusing KN5000 knowledge

**2,302 functions are named for free**, recovered from the firmware's own runtime
reflection tables by [`tools/gen_symbols.py`](tools/gen_symbols.py). The KN7000
runs the same object-oriented "MILK" UI toolkit as the KN5000, and embeds **~114
index-parallel tables** — each a run of code pointers, a NUL, then a run of name
pointers — that its `MT_GetProcedure`-style lookup uses at runtime. The tool
discovers them all generically (a function-prologue check on the paired targets
rejects look-alike event-id / widget-id tables), recovering names like
`SleepMainTask`, `DispatchEvent`, and the whole `Ac*`/`Vw*`/`Ps*`/`Iv*`/`Tt*`
widget window-procedure set (518 `*Proc` + 353 `*Func` handlers) — the **same
names documented for the KN5000** (see the kn5000-docs *Shared Codebase Map*).
The code/name arrays are aligned **directly** (`code[k] ↔ name[k]`) — verified
behaviourally: under this pairing every `Get*` accessor reads its variable and
every `Set*` writes it, with no exceptions (the shifted pairing produced
impossible getters that write memory).

The names land in two places: `kn7000.sym` (a portable `0xADDR name` table) and
`src/symbols.inc` (`.equ` form, `.include`d by `src/program.s` so future
disassembled code can reference functions by name). `make disasm` also emits
`disasm/program_named.asm` — a named, function-by-function listing;
[`disasm/program_named_sample.asm`](disasm/program_named_sample.asm) is a
committed excerpt.

## MN10300 assembler (encoder)

The raw `.incbin` blocks can only become real re-assemblable source once we can
turn MN10300 assembly *back* into bytes. Since no GNU binutils MN10300 target is
available, [`tools/mn10300_asm.py`](tools/mn10300_asm.py) provides one — the
inverse of MAME's disassembler, in unidasm's operand syntax. Validated by
round-tripping every instruction of code region 1 against unidasm
(`tools/validate_asm.sh`):

```
exact byte match : 99.9%
unsupported form :  0.1%   (udf* coprocessor ops + unidasm data-artifacts)
byte mismatch    :  0.01%  (72 cases where the compiler used a non-minimal
                            encoding; ours is a valid shorter encoding)
```

The encoding tables have **zero real errors**; the encoder chooses the smallest
encoding that fits each operand. This is what will let the per-function
`.incbin_range` blocks be converted, one function at a time, into real MN10300
source that still rebuilds byte-for-byte (for the ~99.9% of instructions covered).

`make` regenerates the reference images by invoking the sibling extraction repo,
so the whole chain — original `.SLD` floppies → LZSS decompress → reassemble →
byte-compare — is reproducible from scratch. Override paths if your checkout
differs:

```
make EXTRACT_DIR=/path/to/kn7000_extraction DISKS_DIR=/path/to/KN7000 \
     UNIDASM=/path/to/mame/unidasm
```

## Toolchain

There is no free GNU binutils target for the MN10300 in common distros, so this
project ships its own minimal assembler, [`tools/kn7asm.py`](tools/kn7asm.py)
(pure Python, no dependencies). Its job is reconstruction, not full codegen: it
understands `.byte`/`.word`/`.long`/`.space`, labels/`.equ`/`.org`, and the two
`.incbin` forms. `.incbin_range "file", START, END` asserts that the current
output offset equals `START`, so any gap or overlap in the region layout is
caught immediately.

For **new** code (homebrew apps) there is [`tools/xapasm.py`](tools/xapasm.py), a
two-pass assembler on the same encoder: labels are CPU addresses and may be used
before they are defined, and operands take expressions. Two companions build an
SP7001 SD-card app: [`tools/xap_addon.py`](tools/xap_addon.py) places a module in
the unused tail of the vendor `BASEEXT.XAP` and hooks `XapEntry` to it, and
[`tools/sd_splice.py`](tools/sd_splice.py) overwrites a same-size file in place on
a FAT SD-card image. The demos themselves live in the `kn5000_homebrew` repo
(`demos/kn7000_clock`).

Disassembly listings are produced by **MAME's `unidasm`**
(`unidasm <rom> -arch mn10300 -basepc <cpu_addr>`); `make disasm` drives it.
`disasm/program_entry.asm` (the boot/entry region) and
`disasm/table_directory.asm` are committed as curated samples; the full ~30 MB
linear listing is regenerable and git-ignored.

Some listings are **hand-annotated** rather than generated — currently
[`disasm/debugger_memdump.asm`](disasm/debugger_memdump.asm), the complete
semantic disassembly of the hidden factory MEMORY DUMP hex viewer (its chord
dispatcher, config-byte gate, all ten window-procedure event handlers, and its
static data). Those are not part of the byte-exact build, so
[`tools/verify_listing.py`](tools/verify_listing.py) (`make verify-listings`)
keeps them honest: it re-reads every byte column straight out of `baserom/` and
re-encodes every printed mnemonic with `tools/mn10300_asm.py`. Today it reports
2321 bytes verified with 0 mismatches, 0 unexplained gaps and 803/803
instructions re-encoding byte-identically.

Converted code in `src/program.s` itself can carry the same kind of
interpretation: [`annotations/*.ann`](annotations/README.md) give a converted
function semantic local labels (every branch inside it then names its target),
named data addresses, and header, block and end-of-line comments, all keyed by
CPU address and merged in by `tools/gen_program_s.py`. Since those functions are
part of the build, `make verify` checks them byte for byte, and `kn7asm` checks
each function label against its `.equ` in `src/symbols.inc`.

## Status

100% byte-match achieved; boot header (0x0–0x80) hand-annotated. **`src/program.s`
is organised by the recovered functions** (kn7000.sym reflection names plus the
kn7000_manual.sym hand-recovered names), and **111 functions are now converted
to real, re-assemblable MN10300 assembly**: the task/event and display/object
framework clusters (e.g. `SetVisible`, `DispatchEvent`), the complete
**Techni-Chord harmony engine** (`TechniChordCompute`, the 14 per-style voicing
routines, and their helpers — including the corrected style mapping: parameter
`0x8081` uses a legacy order that the GUI translates through the 14-halfword
table at `0x485EC940`, with `DUET 1` stored last), and the complete
**control-panel serial protocol** (`PanelTransaction`/`PanelTxKick`, the three
ISRs `PanelAtnIsr`/`PanelTxDoneIsr`/`PanelRxIsr`, the 10-state transfer machine
`PanelTxState1..6`/`PanelRxState8..9`, the switch-report frame decoder
`PanelFrameDecode` and the button dispatcher `PanelButtonDispatch` — the chain
whose reverse-engineering drove the MAME HLE bring-up in
`kn7000_mame/notes/panel-serial-protocol.md`; the surrounding FIFO helpers and
switch-event pipeline are named as boundaries in `kn7000_manual.sym`). Call
targets are resolved to labels so the source reads normally, and `kn7asm.py`
assembles it back to the exact ROM bytes. The converted set now contains **zero
`.byte` escapes** outside the annotated boot header: the encoder gained the
`and`/`or imm16, psw` forms, and the generator repairs unidasm's F4-page length
bug (movbu register-indexed ops printed as one byte) from the ROM bytes. Growing the `CONVERT` set in `tools/gen_program_s.py` and
running `make program-src` converts more; the remaining functions stay raw
`.incbin_range` until then. The **display palette** (256-entry `0x00BBGGRR`
CLUT at `0x32573C`) is lifted into typed `.long` source.
See [`kn7000_extraction/NOTES.md`](../kn7000_extraction/NOTES.md) for the memory
map, region map and other findings that guide the work.

## SP7001 firmware (program 942 / table 83)

The KN7000's `sp7001` BIOS (Key Soft Service SD PLUG-iN) is a second byte-exact target, built
by reusing everything recovered for the default build rather than starting over. Program 942
is build 941 plus a few edits (all 2302 reflection names survive, shifted by +0/+2/-17 bytes),
so `tools/offset_map.py` maps every byte exactly and `tools/port_symbols.py` carries the names
across (2291 of 2302 at exactly the address 942's own tables give; 1622 of 1623 manual names).
`gen_program_s.py --profile sp7001` then ports 941's function split, conversions and notes:
544 region-1 + 437 library functions come out as MN10300 assembly. What is new in 942 is a
**plug-in host** (validates and calls an 'XAPR' plug-in at table address `0x483E8000`) and a
**name-based export table** of 231 services for it (uITRON kernel calls, file and compression
APIs, buffer accessors) -- 228 names build 941 never had (`kn7000_sp7001_exports.sym`, pairing
verified against uITRON interrupt semantics). Table 83 is table 84 with 6 small segment changes
plus that plug-in appended, which `tools/gen_table_s.py` disassembles (its own 35 reflection
names; the activation gate named from the earlier reverse-engineering). That plug-in loads
`.XAP` extensions to the fixed RAM address `0x5029B000`; `BASEEXT.XAP`, from the SP7001 table
update, is disassembled too (`tools/gen_xap_s.py`), and the update's two table disks prove
table 83 byte-for-byte. Full measurements and
the edit-site catalogue: [`notes/sp7001-build-diff.md`](notes/sp7001-build-diff.md).

## IC19, the picture ROM

`src/picture.s` rebuilds the 2 MB the CPU sees at `0x57800000` from the chip's own pictures:
a directory of 102 offsets, then the 100 PRESET pictures of the Slide Show, each a 640x240
JPEG in `src/picture/` brought in with `.incbin` and padded with `.align 4`. The read it
reproduces was made on a real KN7000 (PROGRAM 893) on 2026-10-19 with `tools/cnv_romdump`;
`make verify-picture` checks the rebuild against that read's SHA-1, and against the read
itself when it is at hand. Why only 2 MB of a 64 Mbit chip, how the firmware reads it, and
what the pictures are for: [`notes/ic19-picture-rom.md`](notes/ic19-picture-rom.md).

## Manual symbol supplement

`kn7000_manual.sym` hand-names functions that the firmware's own reflection
tables (which produce `kn7000.sym`) leave unnamed -- recovered by reverse-
engineering in the sibling `kn7000_mame` driver effort (panel serial protocol,
MIDI ISRs, button dispatch, tone-generator register writes; see that repo's
`notes/`). `make disasm` merges it with the generated `kn7000.sym`. It does not
affect the byte-exact build (`make verify` stays 100%).
